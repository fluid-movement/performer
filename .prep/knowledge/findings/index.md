# findings

## Entries

* [The five function keys have no LEDs](/findings/01M5M0Y74FWWZ54QPF4T6TR85B.md) - The LED matrix is CONFIG_BLM_ROWS * CONFIG_BLM_COLS_LED = 32 entries covering 8 track, 16 step and 8 global buttons; Key::F0 is already index 32, so writing an F-key LED is an out-of-bounds write. F-key state must be shown on screen (inverted footer tab). Found 2026-08-29.
* [Line-sequencer view: strengths and limits](/findings/01M5M0Y7Z79JZF6SA2EJFZV95D.md) - A horizontal line per active step encodes gate (present), pitch (vertical position) and gate length (width). It reads melody contour well but has under 2px per semitone for a two-octave range in 46px, small width differences are illegible, and beat structure disappears. Proposed fixes: use it on the NOTE tab only, add faint scale-degree rules, vary brightness by beat, and use a full-height scanline play cursor.
* [Curve evalSegment is duplicated in the UI sandbox](/findings/01M5M0Y8410H272KAAMPXJS26X.md) - CurveSequence::evalSegment is reimplemented in tools/ui-sandbox/src/routes/+page.svelte; any change to the curve math must be mirrored there or sandbox curves drift from the firmware.
* [SortedQueue usable capacity is Capacity-1](/findings/01M5M0Y8N982ZNPD4HAXJEVGEQ.md) - SortedQueue::size() is (_write - _read) % Capacity, so a full queue reads as empty. The old note engine pushed 16 events for RETRIG 7 + LENGTH 15 and the step went silent. Never push a whole step's events at once into a 16-slot queue; the note slot scheduler makes overflow structurally impossible.
* [Hardware CV output ceiling is +-5V, not 10V](/findings/01M5M0Y998HJBWJ44QCRBMSR5Y.md) - Calibration::CvOutput spans MinVoltage -5 to MaxVoltage 5 and voltsToValue() hard-clamps there (the ideal DAC/opamp stage gives about +5.17V / -5.25V). Do not offer ranges beyond 5V.
* [SequenceState::direction() must be set by every run mode](/findings/01M5M0Y9E92KC4ANF6PC76PKT3.md) - Until Version53 direction() had no callers and only PingPong, Pendulum and RandomWalk maintained it, so Backward reported +1 and a stale -1 survived run-mode changes. Both calculateNextStepFree and calculateNextStepAligned now set it in every mode; keep it that way when adding run modes.
* [Stochastic bar ghosting on hardware is SSD1322 column coupling](/findings/01M5M0Y9R5RQXKMAKXFMKAZHX9.md) - Probability bars bleed into each other on the real OLED but not in the simulator: SSD1322 column capacitive coupling, not a rendering bug. Bars were thinned to 18px (half the 36px column) and the full column is cleared each frame to stop header-line bleed into gaps. Wide bright adjacent columns are risky on this display.
* [Routing targets degrade gracefully when removed](/findings/01M5M0YAETAVQEGQG3VKBY6YRR.md) - Routes serialize targets by a stable id (targetSerialize) and readEnum falls back to Target::None for an unknown id, so deleting a routing target needs no migration.
* [pybind ignores defaulted routed arguments on setters](/findings/01M5M0YAHA7MTWPTNVNHHT46TF.md) - Binding a Python property directly to a setter with a defaulted routed argument makes assignment raise TypeError; wrap the setter in a lambda in python/project.cpp.
