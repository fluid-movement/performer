* [Design principle: gestalt by default, exact values only while editing](/decisions/01M5M0Y7QQAWF1GRJXC54C0TXE.md) - Idle views communicate shape and contour (line height, width, fill); the exact number appears as a prominent overlay only while a step is held and the encoder turns, and goes away on release. Why: the idle view is navigational and the edit view precise; mixing them clutters both.
* [Design principle: absence is information](/decisions/01M5M0Y7TA0AZCAJ5YDG4EQ0BN.md) - Draw nothing for off states: no dim placeholders, ghost borders or greyed cells. Everything drawn then means something. Mark only what varies: gate presence is boolean, so its mark is small and uniform; length, probability and pitch vary, so their marks vary. Negative space aids scanning; visual weight is not a proxy for importance.
* [Design principle: tabs change the editing target, not the display](/decisions/01M5M0Y7WTJ20X6G2QWSRAWA9J.md) - Switching F-key tabs keeps the base view stable; the tab changes which footer cell is highlighted, what hold+turn edits, and optionally a small additive overlay (scale-degree grid on NOTE, repeat counts on REPEAT). Layered reveal: base gestural layer always, tab overlay, then exact value while a step is held. Why: a full display swap per tab forces the user to re-parse the screen and discards their mental model.
* [UI design iterates in the Svelte sandbox before any C++](/decisions/01M5M0Y81M551JXXSBXYYWF9J9.md) - tools/ui-sandbox is a SvelteKit/Svelte 5 app whose Canvas.ts mirrors src/core/gfx/Canvas.h 1:1 (same colours, fonts, Set/Add/Sub blend), so mockups translate directly to C++. Variations are {label, draw(c), leds()} in VARIATIONS[pageId] in src/routes/+page.svelte; the trunk sits at index 0 labelled TRUNK. The user runs the dev server themselves; agents do not start it. Why: the firmware sim needs a full C++ build per change; the sandbox iterates in seconds.
* [Note track is deterministic; randomness belongs to the Stochastic track](/decisions/01M5M0Y86H9YE8JASRN2VV18SZ.md) - Note V2 (Version54) deleted gate probability, gate offset, retrigger probability, length/note variation range and probability, Bypass Scale and Stage Repeat Mode from steps, and play mode, CV update mode and the four bias parameters from the track. Do not reintroduce per-step randomness on the Note track. The detail popup is gone; values are read from the per-step strip.
* [Note steps: 5 tabs, 10 layers](/decisions/01M5M0Y88ZVB23ZVKATT2C3BV4.md) - GATE (Gate, Step Length, Gate Length), RETRIG (Retrigger, Arp Retrigger), REPEAT (Repeat), NOTE (Note, Slide), COND (Condition, Retrigger Condition). 46 of 64 step bits used; _data1 has 18 spare bits. gate, slide and note kept their pre-Version54 bit positions so the migration copies them straight.
* [Note step length is a ratio of the divisor](/decisions/01M5M0Y8BHWXMVACTG1KD0JJ18.md) - Step Length indexes a 20-entry table 1/8 1/6 1/4 1/3 1/2 2/3 3/4 1 5/4 4/3 3/2 2 5/2 3 4 5 6 8 12 16 (default index 7 = 1/1); stepLengthTicks = max(2, divisor*num/den). A step can be shorter or longer than a clock pulse. The field is 5 bits, so up to 32 entries.
* [Repeat extends a step, Retrigger subdivides it](/decisions/01M5M0Y8DY3A3FZ08RVQSBDBJS.md) - Repeat (1-8) replays the whole step body including retriggers and arp offsets, so the step lasts stepTicks*repeat (Metropolix stage repeats). Retrigger (1-8) slices that body. Arp Retrigger (-15..+15) adds scale degrees per slice and resets each repeat. Gate Length is a percentage of the retrigger slice, not the step, because measured against the step retriggered gates would overlap.
* [Only the gate condition writes the Pre/NotPre chain](/decisions/01M5M0Y8GFXNYYERCXRSGVV2KG.md) - Retrigger Condition uses the same Types::Condition set and, when it fails, collapses the step to retrigger = 1, but it only reads the Pre/NotPre chain. Two writers would make Pre meaningless.
* [Note engine is a slot scheduler with onsets derived from the step start](/decisions/01M5M0Y8JW74E774EMDNVT4103.md) - A step is repeat*retrigger slots scheduled one at a time; beginStep latches per-step decisions at slot 0; slotOnset(k) = _stepStartTick + _stepTotalTicks*k/_totalSlots, never accumulated, so rounding stays bounded and the last slot lands on the step end. Each slot pushes at most 2 gate + 1 CV event. In Retrigger gate mode gate-off is clamped to slotLen-1 so it never coincides with the next gate-on. The slide flag rides only on slot 0, so intra-step arp jumps snap. A gate-off step pushes nothing and changes no CV.
* [Note track has no Aligned play mode and no CV update mode](/decisions/01M5M0Y8QN30F252KJQ93FJKGX.md) - NoteTrack::_playMode was deleted: advanceAligned() derives the step index in closed form from relativeTick/divisor, which variable step length cannot express (the same trade Curve made in Version53). The engine always advances freely. CvUpdateMode was deleted because Always contradicts 'a gate-off step changes nothing'.
* [Note slide is a bounded, constant-time ramp (TB-303 style)](/decisions/01M5M0Y8T126KS0PDYHHA9YCNW.md) - Portamento uses Slide::Ramp + Slide::shape, normalized so shape(0)=0 and shape(1)=1 for Linear, Exponential (default, RC/303) and Logarithmic, so arrival is guaranteed. slideTime is milliseconds (value*5, 5-500 ms, default 60 ms). Why: the old one-pole (tau = 2*(slideTime/100)^2 s) never converged, covering about 22% of the interval in a 1/16 step at 120 BPM; the TB-303 glide is constant-time (~55 ms), exponential and bounded. Slide::applySlide stays for CurveTrackEngine's slew limiter, which genuinely wants a lag that never settles.
* [Gate Mode: Retrigger by default, Legato holds 100% gates across the boundary](/decisions/01M5M0Y8WNQMB8T9S73VC0GZJ6.md) - At 100% gate length, Legato holds the gate across the step boundary and suppresses the next slot's gate-on; Retrigger (default) closes it one tick early so it can re-fire.
* [Curve track is a segment assembler](/decisions/01M5M0Y8Z3AWV8S9AFJWA064FG.md) - Steps are segments that chain and loop; loop length is the sum of segment lengths. Tabs SHPE / SKEW / LEN / LVL / OFST. Each segment rises from offset to offset+level and back, shaped by evalSegment(phase, shape, skew, expCurve); a short gate fires at each segment start. Step buttons select segments (up to 16). Legacy bitfield names Min/Max/ShapeVariation now mean offset/level/skew.
* [Curve parameters edit in an integer 0-100 percent domain](/decisions/01M5M0Y91KC2XDD1MX6ZKW1E1M.md) - All five curve params edit via shapePercent()/skewPercent()/levelPercent()/offsetPercent(): 1 unit per detent, SHIFT = x10 coarse (the firmware-wide coarse convention). The percent round trip is exact, which keeps stepping symmetric. Why: the old 0.05f float step plus re-quantization stepped +3/-2 raw. The same encoder logic is duplicated in OverviewPage and must be changed in both.
* [Curve SHPE: exponential fall at the low end, flat hold at the top](/decisions/01M5M0Y946XE7W585QYYN8DHP8.md) - SHPE 0-50 blends a normalized exponential fall into the half sine (m = shape*2, k = (1-m)*expCurve), giving a cusp at the peak for percussive envelopes; SHPE 50-100 is sine^p widening to a flat hold (p <= 0 returns 1). Steepness is the per-track Shape Curve setting: Gentle 4 / Medium 6 (default) / Snappy 8. Skew endpoints are exact, not clamped: skew 0 = instant attack, skew 100 = instant release. Why: every power of a sine has zero slope at the peak, so it can only make a rounded top.
* [Curve output is unipolar 0V..Range, Range 1V-5V on the track](/decisions/01M5M0Y96QJK8YFSBSBT41VB3V.md) - Range lives on CurveTrack (Version52), restricted to Unipolar1V..Unipolar5V; bipolar values map to the unipolar entry of the same voltage. Bipolar output is reached through the track Offset (Range 0..5V with Offset -2.50V gives -2.5..+2.5V). editRange clamps as int before converting because VoltageRange is uint8_t backed and a negative would wrap to 5V.
* [Curve plays segments mirrored when travelling backwards](/decisions/01M5M0Y9BSWC78SQQWSJZ7Q0P1.md) - phase = direction() < 0 ? 1 - fraction : fraction. Backward mirrors everything including the wrap; Pendulum/PingPong mirror the descending leg; RandomWalk mirrors when it steps back; Random never mirrors. The play scanline uses the mirrored phase; the drawn curve is never mirrored; the gate still fires at the segment start. A rule based on step deltas was rejected: it breaks on Backward's wrap and Pendulum's repeated endpoint. Version53.
* [Curve track has no play mode, fill mode, min/max or probability biases](/decisions/01M5M0Y9GS27Z4HY4W6B9NNZDE.md) - Removed as dead code: curveMin/curveMax and shape/gate probability biases with routing targets CurveMin (39), CurveMax (40), ShapeProbabilityBias (22) in Version52; playMode and fillMode in Version53 (engine always uses advanceFree; _fillSequence was never read). GateProbabilityBias (9) stays for Note/Arp/Stochastic.
* [Stochastic track V2 is SIG-inspired probability distributions](/decisions/01M5M0Y9K7NDNR9TEK7FGGM38X.md) - Three global distributions sampled every step: 7 scale-degree bars (NOTE), 5 octave bars -2..+2 (OCT), 6 duration bars 1/16..2 (LEN). Rest density is implicit: the total degree probability mass drives it, with no separate rest parameter. If all degree weights are 0 the engine falls back to equal weighting rather than going silent. Edit by holding a step and turning. Tabs NOTE / OCT / LEN / LOOP; SIG's articulation (ART) was dropped because the module has no envelope output. No migration from the old per-step model (Version44).
* [Stochastic LOOP: Turing-machine style mutation with its own RNG](/decisions/01M5M0Y9NPD38A4YK0R8EAV2WW.md) - Step buttons set loop length (1-16), the encoder sets loopChance (0 = locked, 15 = fully random); each replayed step has a per-step chance of being redrawn from the current distributions. Mutation uses a separate mutationRng so it does not disturb the sequence RNG stream. Loop length is stored as _loopLength (Version45), decoupled from firstStep/lastStep; the buffer is read as (firstStep + index) % 16, so firstStep shifts phase without changing length.
* [Arp track V2: degree-mask note pool + two euclidean generators](/decisions/01M5M0Y9TKGVHYRJF5Q8C96BMB.md) - 7-bit degreeMask selects active scale degrees (no per-step notes, no MIDI input). A rhythm euclidean (N/K/R + gate length) drives gates; a mod euclidean (N/K/R + mode Off/Accent/Mask/Combine/Ratchet/Hold) acts on rhythm hits. Orders UP/DOWN/UP-DN/DN-UP/RAND, with bounce modes using period 2*(n-1) so endpoints do not repeat. Tabs NOTE / RHYTHM / MOD / ARP. Version46, no migration from the old per-step model. Arp has no play mode (removed in Version49; only Aligned ever worked).
* [Euclidean patterns use canonical form, shared by engine and display](/decisions/01M5M0Y9X2RXJFV1T4PBS5P5RP.md) - computeEuclidean puts the first hit at step 0 and applies the user's rotation on top. The engine and ArpSequenceEditPage both call the single implementation in engine/EuclideanGenerator.h (the test arp_v2_test.py mirrors it). Why: the display used to auto-rotate independently, so MASK/COMBINE overlap cells disagreed with the real gate output.
* [Quantizer V2: 5 tabs and a unified 13-position trigger source](/decisions/01M5M0Y9ZJ4QVR4YET3JXMF907.md) - Tabs GATE / SRCE / TRIG / TUNE / LOOP. TRIG is one scroll FREE -> INT+T1..T8 -> EXT+CV1..CV4 backed by a single TriggerSource list row (editTriggerSource/printTriggerSource). CvGate mode (Version48) fires on a CV input rising edge. Old Internal mode loads as Free. Spurious-edge guards _lastCvChannel (CvGate) and _lastTriggerTrack (External) absorb a HIGH input on mode or channel switch. Scale/root are global; the quantizer has no per-track scale.
* [Quantizer always-on clock and loop rules](/decisions/01M5M0YA272XNPH9ZBZGHMC1QS.md) - The sequence clock sets _samplePending every tick in all modes and gate+CV commit atomically in commit() SampleDelayTicks after the boundary. Free mode gets no clock-driven sample outside Loop: hysteresis is its only commit path (prevents Rec double-fill). In Loop, External/CvGate do not set samplePending; the loop advances from the clock only, preventing double-advance of _loopIndex. The loop buffer stores un-transposed note indices; octave/transpose apply live at playback.
* [Quantizer input stability: IIR + hysteresis + delayed sampling](/decisions/01M5M0YA4NAHB4BBV86JAT5BE5.md) - InputFilterAlpha 0.10 IIR, HysteresisVolts 0.012 (~14% of a semitone, Free mode), SampleDelayTicks 4 (~10 ms) before committing in clocked modes. Every scale step is >= 83 mV and FilterSnapVolts is 50 mV, so real pitch changes bypass the IIR; it only damps sub-note jitter. Alpha 0.10 beat 0.25 for mid-frequency interference (stable to +-30 mV p-p at 33 Hz vs +-10 mV). Noise of +-30 mV or more near a boundary cannot be guaranteed stable; recommend hardware filtering.
* [Step notes are scale degrees; scale and root are project-global](/decisions/01M5M0YA770KSWWPAPPNJWWB5T.md) - step.note() stores a scale-degree index, never a semitone. Scale and root note live on the project only (per-sequence scale removed in Version41). Changing the scale never remaps step notes: the same degree pattern plays in the new harmonic context, which makes sweeping the scale a sound-design move. Never use Scale::isNotePresent on a degree (it expects a chromatic semitone), and never assume Scale::get(0) is chromatic.
* [Built-in scales are 21 seven-degree modes; there is no chromatic scale](/decisions/01M5M0YA9Q0RJNMRF5SPGJD53W.md) - 7 diatonic, 7 harmonic-minor and 7 melodic-minor modes, labelled Maj:/HM:/MM:; index 0 is Maj: Ionian, so degree 1 is 2 semitones. Semitones and Voltage scales were removed (2026-05 clean break). Scale indices are stored raw in project files, so reordering the table is a breaking change.
* [Breaking model changes bump ProjectVersion and migrate in read()](/decisions/01M5M0YAC9GWPQC8SWRG6VSP91.md) - Each serialization change adds a ProjectVersion entry and version-gated reads (reader.read(field, VersionN), reader.skip<T>(0, VersionN) for removed mid-blob fields). write() keeps writerVersion() branches emitting zeroed placeholders for older formats, because the Python harness writes old versions to test the read migrations. Removed Routable<float> fields were written whole (8 bytes), not .base. Clean breaks without migration are acceptable before outside users (Curve V1, Stochastic V2, Arp V2 did that), but say so in the change.

Legacy bitfield names Min/Max/ShapeVariation now mean offset/level/skew. Layers, tabs and math are in agent-docs/features/curve-track.md.
* [Quantizer trigger source is one unified scroll and Internal mode is retired](/decisions/01M5M4S1QVGN2TXZWQDD5TK67J.md) - Trigger mode and track/channel are edited as a single 13-position TriggerSource row (Free, External+T1..T8, CvGate+CV1..CV4); old Internal loads as Free (Version48); scale and root are global. Tabs and engine flow are in agent-docs/features/quantizer-track.md.
* [Arp track has a degree-mask note pool and no per-step notes or MIDI input](/decisions/01M5M4S1ZVE8P1EWGS6X03GG3M.md) - Notes come from a 7-bit degree mask, rhythm and mod are two euclidean generators, and Version46 gave no migration from the old per-step model. The play mode was removed in Version49 (only Aligned ever worked). Fields and tabs are in agent-docs/features/arp-track.md.
* [Stochastic track samples three global distributions and stays silent when all degree weights are 0](/decisions/01M5M4S27KRA63R31QSPGVVS07.md) - Degree, octave and duration probability bars are sampled every step; rest density is implicit in the degree mass; ART was dropped; no migration from the per-step model (Version44). Correction: with all degree weights 0 the engine is silent (test_all_degrees_zero_no_gate), not equal-weighted as the replaced record claimed. Details in agent-docs/features/stochastic-track.md.
* [Stochastic loop mutation uses its own RNG and a loop length decoupled from first/last step](/decisions/01M5M4S2F9T7S46M9MGVTW0EY9.md) - Replayed slots are re-drawn with probability loopChance/15 using a separate mutationRng so the sequence RNG stream is undisturbed, and loopLength (Version45) is independent of firstStep/lastStep, which only shifts the loop's phase in the 16-step buffer. Tab controls are in agent-docs/features/stochastic-track.md.
