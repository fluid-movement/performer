# Information Architecture — Decided

This document defines the new page structure. It is a **decision record**, not a strawman.

---

## Design principles

1. **Joy first** — the UI should feel alive, precise, and satisfying. The module is an instrument.
2. **Labeled by default, fast for experts** — every primary action has a visible label. Power-user shortcuts exist but are never required.
3. **Three tiers** — Jam (instrument surface), Quick (on-the-fly edits), Set-and-forget (config).
4. **Hardware is fixed** — 256×64 mono OLED, 8 Track + 16 Step + 5 F + 8 Global buttons, 1 encoder, 32 bi-color LEDs.
5. **Remove complexity that doesn't earn its place.**
6. **Animation earns its place** — motion only when it conveys state (play cursor, beat pulse). Visual clutter is bad design.

---

## Interaction model

### Encoder
- **Encoder press is removed.** Do not design interactions that require pressing the encoder.
- **Universal value-change pattern: hold target button + rotate encoder.** The held button identifies which parameter changes. This mirrors Page+X for navigation.
- **Idle rotate (no button held)** is page-type-dependent:
  - List/settings pages: scrolls the cursor.
  - Jam pages: adjusts the most obvious contextual value when one is unambiguous (e.g., selected step's note on a note track). Otherwise no-op.

### F-keys
- **F-key footer is present on every page.** It is never removed.
- **All 5 F-keys are free per page** — no slot is globally reserved.
- **Primary use: tabs within a page** (layer families, sections, parameter groups).
- Secondary use: page-specific actions where tabs don't apply.

### Header
- **Optional per page.** The footer is the consistent chrome; a header strip at the top (showing page/track context) is included only when the design needs it. Goal: a system strong enough to not need headers.

### Brightness
- **3 levels only — Bright (15) / Low (≈3–5) / off.** No mid-tones.
  - Bright = focused / active / in-use.
  - Low = context / structural / present-but-not-the-point.
  - Off = absent. True black = not here. Do not draw dim fills for "inactive" — absence IS the signal.

### LEDs
- **32 bi-color LEDs are first-class design surface.** Every page design includes both screen and LED state. Red / green / blink semantics are defined per page in the design language doc (`01-design-language.md`).

## Features removed

These are cut from the new UI. The underlying model code can be removed when each page/track type is rebuilt.

| Feature | Reason |
|---|---|
| Micro tuning / BypassScale | Obscure, rarely used, already partially removed |
| RetriggerProbability | Sub-layer too deep; direct retrigger is enough |
| StageRepeats / StageRepeatsMode | Too complex for the jam ethos |
| NoteVariationRange + NoteVariationProbability | Sub-layer; generative variation belongs in Stochastic, not hidden in Note |
| Logic track | Already removed |
| LayoutPage (global CV/gate matrix) | CV/gate N → track N is the sane default; advanced assignment buried in Track Config |
| 5× SequencePage variants (thin ListPages) | Content already accessible via quick-edit overlays |

## Page map

### Tier 1 — Jam (instrument surface)

---

#### Dashboard
**Replaces:** OverviewPage (was buried at Page+Left)  
**Hardware reach:** Performer key (one press, no modifiers)

The default home screen. Shows the whole project at a glance.

**On screen:**
- Optional header: play/stop · current pattern · clock source (no BPM — tempo has its own modal)
- 8 track rows: track number · type glyph · 16-step gate pattern with current-step cursor · mute state
- F-key footer: page-specific actions (TBD — design in dedicated Dashboard session)

**Navigation — Page+X combos (unchanged from current firmware):**
- Page+Step0 → Track Edit
- Page+Step2 → Track Config
- Page+Step3 → Song
- Page+Track0–4 → Settings sections
- Page+Left → Dashboard (home)
- Pattern key → Perform
- Tempo key → Tempo modal
- Track N → select track N

> **BPM** is not shown on Dashboard — it lives in the Tempo modal only.

---

#### Perform
**Replaces:** PatternPage + PerformerPage (was two separate pages with modal/pinned duality)  
**Hardware reach:** Pattern key (one press, no modifiers)

One screen for all live performance control — patterns, mutes, fills, chaining.

**On screen:**
- 8 track columns, each: track number · current/requested pattern indicator · 16-pattern mini-grid · mute state · fill bar
- Status strip: sync/latch mode indicator (no BPM — Tempo modal only)
- F-key footer: `LATCH · SYNC · SNAP · FILL · (TBD)`

**Key interactions:**
- Step N → change playing pattern to N
- Track N → toggle mute
- Shift + Track N → solo
- F0 (LATCH) / F1 (SYNC) held → latched/synced changes
- F2 (SNAP) → snapshot
- F3 (FILL) held → fill all tracks
- Step 8–15 held → fill track (step − 8)
- Hold Step A + Step B → **quick chain** (play A then B, looping). For complex multi-track song arrangements, use Song.
- Shift + Step N → set edit pattern

---

#### Track Edit
**Replaces:** NoteSequenceEditPage, CurveSequenceEditPage, StochasticSequenceEditPage, ArpSequenceEditPage, QuantizerSequenceEditPage (5 separate pages)  
**Hardware reach:** Page+Step0 (or F-key shortcut from Dashboard — TBD per type)

**5 type-specific pages, not one adaptive page.** Each track type (Note, Curve, Stochastic, Arp, Quantizer) gets its own visual design because the editing paradigm differs substantially (e.g., Curve has no notes; Quantizer has no per-step gates). However, all 5 share:
- The **F-key footer as tabs** (layer families for this track type — content varies)
- **Consistent interaction conventions** (step selection, quick-edit overlay, section navigation, undo)
- **Optional header** — decided per track type in their dedicated design sessions

**Shared conventions (all track types):**
- F0–F3 = layer family tabs for this track type
- Step selection: Immediate (hold) and Persist (Shift+step) modes
- Quick-edit overlay via Page+Step8–14 (FirstStep, LastStep, RunMode, Divisor, ResetMeasure — slots 8–12)
- **Quick-edit legend:** When Page is held, the display briefly shows parameter names mapped to Step8–14 so users don't need to memorize slot numbers
- Section navigation: Left/Right for 64-step sequences
- MIDI note input when steps are selected and not recording
- Undo: Page+Step6 reverts to snapshot

**Per-type visual and tab design:** Covered in dedicated sessions. Order: Note → Curve → Stochastic → Arp → Quantizer → MidiCv. See `06-track-type-inventory.md` for parameter inventory per type.

### Tier 2 — Quick (on-the-fly)

---

#### Quick-Edit Overlay
**Unchanged interaction, improved labeling** (as described in Track Edit above)

Parameters: FirstStep, LastStep, RunMode, Divisor, ResetMeasure (slots 8–12). Slots 13–14 are `—` for now.

---

### Tier 3 — Set and forget

---

#### Track Config
**Replaces:** TrackPage + LayoutPage (global view is gone — buried in Settings under Layout)  
**Hardware reach:** F2 from Dashboard, or Page+Step2

All per-track settings on one adaptive page, organized by section (idle encoder rotate scrolls cursor; Track key jumps sections).

**Sections:**
- **Type & mode** — track mode (Note/Curve/Stochastic/Arp/Quantizer/MidiCv), name, play mode, fill mode, link target
- **Timing** — divisor, reset measure, slide time
- **Tuning** — (Note/Stochastic/Arp) octave offset, transpose
- **Output** — CV output assignment, gate output assignment (advanced; default = track N → jack N)

F-key footer: `EDIT · · · · ↩` (F0 = jump to this track's Track Edit; F4 = back)

---

#### Song
**Deferred.** Design after Dashboard, Perform, Track Edit, and Settings settle — the shared patterns learned from those pages will inform the Song layout. Quick chain (hold two steps in Perform) handles the immediate live-performance case. Song handles the full case: multi-track pattern assignments, repeat counts, per-slot mute states. Stays Tier 3.

---

#### Settings
**Replaces:** ProjectPage, RoutingPage, MidiOutputPage, UserScalePage, ClockSetupPage, SystemPage  
**Hardware reach:** F4 from Dashboard, or Page+Track0..4 (kept as expert shortcut)

Sections (idle encoder rotate scrolls sections; F-key tabs or Track key jumps directly):
- **Project** — name, global scale, root note, time signature, save/load (SD card)
- **Clock** — source, PPQN, swing, sync pulse
- **Routing** — 16 routing slots
- **MIDI** — MIDI output slots + port config
- **Scales** — 4 user scale slots
- **Layout** — compact global CV/gate assignment table (all 8 tracks; for when the default doesn't fit your patch)
- **System** — calibration, update/reset

F4 (↩) → Dashboard

## Navigation map

```
Performer key ──────────── Dashboard (home)
Pattern key ────────────── Perform
                           (modal-hold or Page+Pattern for non-modal)

Global (from any page):
  Track N → select track N
  Play → toggle play/stop
  Tempo → Tempo modal (always modal)
  Page + Left → Dashboard (home)

Page+X shortcuts (expert; unchanged):
  Page + Step0 → Track Edit (active track type)
  Page + Step2 → Track Config
  Page + Step3 → Song
  Page + Track0 → Settings (Project)
  Page + Track2 → Settings (Routing)
  Page + Track3 → Settings (MIDI)
  Page + Track4 → Settings (Scales)
  Page + Track7 → Settings (System)
  Page + Tempo  → Settings (Clock)

F-keys: page-specific tabs/actions (no global destinations — see each page's footer)
```
